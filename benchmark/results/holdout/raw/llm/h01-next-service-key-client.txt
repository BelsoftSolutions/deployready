**Remediation, in priority order:**

1. **Rotate the service role key now.** Because it has been shipped in the client bundle, treat it as compromised, even if you have not seen abuse. Rotate it in the Supabase dashboard and update any server-side deployments.
2. **Remove the service role key from client code.** Delete `NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY`. In the browser, use only `NEXT_PUBLIC_SUPABASE_URL` and the anon key (`NEXT_PUBLIC_SUPABASE_ANON_KEY`). Keep any service role key in a server-only variable without the `NEXT_PUBLIC_` prefix, and use it only in server components, route handlers, or server actions.
3. **Enable RLS on `todos`** and add policies that scope access to the owner, for example `using (auth.uid() = user_id)`. Then filter queries by user as well. Confirm RLS is enabled, since the anon key is only as safe as the policies behind it.
4. **Handle errors explicitly.** Check `error` from the Supabase response and show or log it instead of rendering an empty list.
5. **Upgrade Next.js** to a patched 14.2.x release (25 or later) or to a currently supported major version, then re-audit dependencies with `npm audit`.
