**Priority fix for the messages table** (run as a new migration, since the existing one has already been applied):

```sql
alter table public.messages enable row level security;
alter table public.messages alter column sender_id set not null;

create policy "insert own messages" on public.messages
  for insert to authenticated
  with check (auth.uid() = sender_id);

-- Define read access based on your conversation model. Until then, deny by default.
-- Example for a sender-only read policy:
create policy "read own messages" on public.messages
  for select to authenticated
  using (auth.uid() = sender_id);
```

The read policy above is a placeholder. The schema has no recipient or conversation column, so you will need to add one (for example, a `conversation_id` with a membership table) and write the select policy against it. Until you do, the table is locked to everyone except the messages' senders.
